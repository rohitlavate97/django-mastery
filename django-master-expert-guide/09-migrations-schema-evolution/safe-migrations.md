# Safe Migrations
[DJANGO 6.1+] [POSTGRESQL-ONLY]

## Zero-downtime Expand/Contract pattern
Phase 1: Expand (Add new column)
Phase 2: Migrate (Backfill data)
Phase 3: Contract (Remove old column)

```python
# Safe Migration with Lock Timeout
from django.db import migrations

class Migration(migrations.Migration):
    atomic = False
    operations = [
        migrations.RunSQL("SET lock_timeout TO '2s';"),
        # ... other operations
    ]
```

## 6. Anti-Patterns
🔴 **TICKING TIME BOMB:**
Doing blocking operations without timeouts.
```python
# BAD
cursor.execute("ALTER TABLE my_table ADD COLUMN new_col VARCHAR(100);")
```

## 8. Local Development Issues
🔴 SYMPTOM: `django.db.utils.OperationalError: database is locked`
🔍 CAUSE: Concurrent writes in SQLite during local dev.
🔧 FIX: Switch to Postgres in local dev or use higher timeout.

## 9. Production Issues (INCIDENT RUNBOOK)
🔴 INCIDENT: SEV-1 - Database Lockup during Deployment
- **Severity**: High
- **Investigation**: `pg_stat_activity` showed `ACCESS EXCLUSIVE` lock waiting.
- **Root Cause**: `ALTER TABLE` blocked by long-running `SELECT`.
- **Fix**: Terminate blocking query, use `lock_timeout`.

| Concurrent Index | Large tables | No locks, but takes longer |
